# بوابة أنوار لواجهات API

هذه البوابة وسيط محدود الوظائف لخدمات بيانات مفكرة أنوار. ليست وكيل URL مفتوحًا، ولا تقبل عنوانًا خارجيًا يختاره الزائر.

## المسارات المسموحة

- `GET /v1/reciters` — قائمة القراء من MP3Quran.
- `GET /v1/radios` — قائمة المحطات من MP3Quran.
- `GET /v1/country/list?nationality=MA&page=1` — صفحة بلد من Way2Quran. رموز البلدان مقيدة بالقائمة الموجودة في الكود.
- `GET /v1/country/profile?slug=...` — ملف قارئ من Way2Quran، مع فحص صيغة المعرّف.

أي مسار آخر أو أي مضيف خارجي يحدده العميل مرفوض.

## حدود الطلبات المبدئية

الحدود نافذة منزلقة مدتها 60 ثانية:

| الفئة | الحد |
|---|---:|
| جميع الزوار معًا على البوابة | 50 طلبًا |
| عنوان IP واحد، كل المسارات | 30 طلبًا |
| فهرس القراء والمحطات لكل IP | 20 طلبًا |
| صفحات البلدان لكل IP | 8 طلبات |
| ملفات القراء لكل IP | 12 طلبًا |

تسبق هذه الحدود طبقة Rate Limiting binding عند الحافة بحد تقريبي 400 طلب/دقيقة لكل مركز Cloudflare؛ وهي حاجز إسعافي محلي وليست سقفًا عالميًا دقيقًا. بعد ذلك يفحص Durable Object عالمي واحد سقف الموقع وسقف IP ونوع المسار في طلب داخلي واحد. تُستخدم HMAC للعنوان بدل IP الخام، ويتطلب ذلك سرًا خاصًا في Cloudflare باسم `IP_HASH_SECRET` (32 محرفًا على الأقل)، لا يُحفظ في GitHub.

**تحسين الخطة المجانية:** تحفظ عدادات النافذة في كائن واحد داخل SQLite-backed Durable Object، ويجري تحديث صف تخزين واحد لكل طلب مقبول بدل ثلاثة صفوف. سقف 50/دقيقة يعني حدًا أقصى نظريًا قدره 72,000 طلب مقبول يوميًا، دون حصة Cloudflare Free البالغة 100,000 طلب Worker و100,000 طلب Durable Object يوميًا، مع هامش للاستخدام العادي. الطلبات المرفوضة ما زالت تستهلك طلب Worker وطلب Durable Object؛ لذلك لا يعد هذا وحده حلًا لهجوم موزع كبير. صد الهجمات قبل دخول Worker يتطلب نطاقًا تملكه وربطه بـCloudflare واستخدام WAF/Rate Limiting Rules.

**ملاحظة عدالة:** قد يشترك زوار شبكات الهاتف في عنوان IP عام واحد، فيتشاركون حد IP. الحدود مبدئية وتُراجع بعد مراقبة الاستخدام. حد الحافة 400/دقيقة تقريبي لكل مركز Cloudflare وليس عالميًا.
## حدود خطة Cloudflare

يمكن استخدام SQLite Durable Objects على Workers Free. لكن حدود Worker المجانية وDurable Objects المجانية تُحسب يوميًا، وتختلف عن حدود الدقيقة التي يفرضها الكود. توضح Cloudflare حاليًا حد 100,000 طلب Worker يوميًا وحد 100,000 طلب Durable Object يوميًا للخطة المجانية؛ وبعد تجاوز حد يومي مجاني تتوقف العمليات من النوع المتجاوز إلى وقت إعادة الضبط. لذلك تُستخدم البوابة في البداية لعدد زوار محدود وتُراقب لوحة الاستخدام قبل توسيعها.

## النشر عبر GitHub Actions

أضيف سير عمل يدوي في `.github/workflows/deploy-anwar-api-gateway.yml`. بعد إضافة الأسرار الثلاثة إلى إعدادات مستودع GitHub، افتح تبويب Actions وشغّل `Deploy Anwar API Gateway`.

الأسرار المطلوبة في GitHub Repository Settings → Secrets and variables → Actions:

- `CLOUDFLARE_API_TOKEN`: رمز API مخصص لـCloudflare Workers ومقيد بحسابك فقط.
- `CLOUDFLARE_ACCOUNT_ID`: معرّف حساب Cloudflare.
- `IP_HASH_SECRET`: سر عشوائي من 32 بايت على الأقل، ويستخدمه العامل لبصمة HMAC. لا تضعه في ملف أو كود داخل المستودع.

ينشئ سير العمل سر `IP_HASH_SECRET` داخل Worker باستخدام Wrangler Action، ثم ينشره. لا يطبع السر في سجل التشغيل. يوصى باستخدام قالب `Edit Cloudflare Workers` عند إنشاء رمز Cloudflare وتقييده بحساب واحد فقط. قد يتطلب إنشاء Worker جديد صلاحية إدارة Workers بحسب أدوار الحساب؛ لا توسع صلاحيات الرمز إلا عند ظهور رسالة رفض محددة.

بعد النشر، استخرج عنوان `workers.dev` من سجل عملية النشر. ضع هذا العنوان في `api-gateway-config.js` تحت `ANWAR_API_GATEWAY_BASE`، ثم ارفع إصدارًا جديدًا من Service Worker (غيّر `CACHE_NAME` من `v56` إلى `v57`) حتى لا يستمر الزوار في استخدام الإعداد المخزن الفارغ.

القيمة الفارغة في ملف الإعداد تعني أن التطبيق يظل على نمط الاتصال المباشر بالمصادر؛ **لا تصبح البوابة نشطة للزوار قبل نشر Worker وضبط عنوانه في ملف الإعداد**.
## الاختبار بعد النشر

- افتح `/v1/reciters` و`/v1/radios` من صفحة المفكرة.
- راقب عمود Network: يجب أن تمر الطلبات عبر عنوان Worker بدل MP3Quran أو خدمات CORS proxy.
- كرر طلبات الاختبار من نفس الشبكة حتى تتلقى `429` مع `Retry-After`.
- تأكد أن طلبًا إلى مسار عشوائي أو URL خارجي يُرفض.
- تحقق من أن إعادة فتح الإذاعة خلال صلاحية الكاش لا تضيف طلبًا إلى مزود البيانات.

## حدود هذه الطبقة

هذه البوابة تحمي طلبات **البيانات** التي تمر عبرها. ملفات MP3 والبث المباشر ما زالت تُحمّل من مضيفي الصوت مباشرة حتى لا نمرر تدفقًا كبيرًا عبر Worker. كما أنها لا تمنع هجومًا موزعًا واسعًا من آلاف العناوين على Worker نفسه؛ عند ربط نطاق مخصص بـCloudflare يمكن إضافة WAF Rate Limiting Rules وتحديات البوتات عند الحافة. لا تجعل CORS وحده وسيلة مصادقة؛ يمكن لأي عميل غير متصفح تزوير ترويسة Origin.
