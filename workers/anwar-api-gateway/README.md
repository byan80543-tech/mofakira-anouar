# بوابة أنوار لواجهات API

هذه البوابة وسيط محدود الوظائف لخدمات بيانات مفكرة أنوار. ليست وكيل URL مفتوحًا، ولا تقبل عنوانًا خارجيًا يختاره الزائر.

## المسارات المسموحة

- `GET /v1/reciters` — قائمة القراء من MP3Quran.
- `GET /v1/radios` — قائمة المحطات من MP3Quran.
- `GET /v1/country/list?nationality=MA&page=1` — صفحة بلد من Way2Quran. رموز البلدان مقيدة بالقائمة الموجودة في الكود.
- `GET /v1/country/profile?slug=...` — ملف قارئ من Way2Quran، مع فحص صيغة المعرّف.

أي مسار آخر أو أي مضيف خارجي يحدده العميل مرفوض.

## سياسة الوصول الافتراضي بالرفض

يفرض العامل جدول وصول خادميًا صريحًا قبل تشغيل أي معالج أو الاتصال بمخزن البيانات أو بالمصادر الخارجية. لا يُسمح إلا بالمسارات والطرق التالية:

| المسار | الطريقة | مستوى الوصول |
|---|---|---|
| `/v1/reciters` و`/v1/radios` | GET | عام |
| `/v1/country/list` و`/v1/country/profile` | GET | عام |
| `/v1/adhkar` | GET | قراءة عامة |
| `/v1/admin/session` | POST | محاولة إنشاء جلسة مالك بعد التحقق من السر |
| `/v1/admin/adhkar` | GET / POST / PUT | جلسة مالك موقعة مطلوبة |
| `/v1/admin/adhkar/initialize` | POST | جلسة مالك موقعة مطلوبة |
| `/v1/admin/adhkar/{id}` | DELETE | جلسة مالك موقعة مطلوبة |

أي مسار غير مسجل يُرفض بـ `404`، وأي طريقة غير مسموحة لمسار معروف تُرفض بـ `405` مع ترويسة `Allow`. وتُضبط طرق CORS المسموحة لكل مسار بدل إعلان جميع الطرق لكل المسارات. لا توجد في هذه البنية الحالية واجهات حسابات مستخدمين أو موارد شخصية لكل مستخدم؛ لذلك لا تُضاف مسارات افتراضية مثل `/v1/me/*` ولا يُدّعى وجود فحص ملكية سجلات مستخدمين غير موجودة.

جدول المسارات لا يحل محل مصادقة الإدارة: كل قراءة إدارية أو كتابة أو حذف ما زالت تتطلب جلسة مالك موقعة صالحة، ويظل فحص الجلسة وتحديد المعدل على الخادم إلزاميين. ترويسة `Origin` وCORS قيود متصفح إضافية وليستا إثبات هوية؛ طلب يحمل Origin مسموحًا دون جلسة مالك صحيحة لا يحصل على أي صلاحية إدارية.

اختبارات العامل تتحقق من رفض المسارات المجهولة، والطرق غير المسموحة، وبقاء القراءة العامة متاحة، ورفض الوصول الإداري دون جلسة حتى عند إرسال Origin مسموح.

## حدود الطلبات المبدئية

الحدود نافذة منزلقة مدتها 60 ثانية:

| الفئة | الحد |
|---|---:|
| جميع الزوار معًا على البوابة | 50 طلبًا |
| عنوان IP واحد، كل المسارات | 30 طلبًا |
| فهرس القراء والمحطات لكل IP | 20 طلبًا |
| صفحات البلدان لكل IP | 8 طلبات |
| ملفات القراء لكل IP | 12 طلبًا |
| دخول إدارة المالك لكل IP | 20 محاولة فاشلة خلال 15 دقيقة؛ المحاولات الناجحة لا تزيد عداد الفشل |

تسبق هذه الحدود طبقة Rate Limiting binding عند الحافة بحد تقريبي 50 طلب/دقيقة لكل مركز Cloudflare؛ وهي حاجز إسعافي محلي وليست سقفًا عالميًا دقيقًا. بعد ذلك يفحص Durable Object عالمي واحد سقف الموقع وسقف IP ونوع المسار في طلب داخلي واحد. يُطبّق حد دخول المالك على عنوان IP فقط، ولا يُقفل حساب المالك أو هويته؛ تُسجّل المحاولات الفاشلة فقط ضمن نافذة منزلقة مدتها 15 دقيقة، وتُستثنى المحاولات الناجحة. تُستخدم HMAC للعنوان بدل IP الخام، ويتطلب ذلك سرًا خاصًا في Cloudflare باسم `IP_HASH_SECRET` (32 محرفًا على الأقل)، لا يُحفظ في GitHub.

**تحسين الخطة المجانية:** تحفظ عدادات النافذة في كائن واحد داخل SQLite-backed Durable Object، ويجري تحديث صف SQLite واحد لكل طلب مقبول بدل ثلاثة صفوف. سقف 50/دقيقة يعني حدًا أقصى نظريًا قدره 72,000 طلب مقبول يوميًا، دون حصة Cloudflare Free البالغة 100,000 طلب Worker و100,000 طلب Durable Object يوميًا، مع هامش للاستخدام العادي. الطلبات المرفوضة ما زالت تستهلك طلب Worker وطلب Durable Object؛ لذلك لا يعد هذا وحده حلًا لهجوم موزع كبير. صد الهجمات قبل دخول Worker يتطلب نطاقًا تملكه وربطه بـCloudflare واستخدام WAF/Rate Limiting Rules.

**ملاحظة عدالة:** قد يشترك زوار شبكات الهاتف في عنوان IP عام واحد، فيتشاركون حد IP. الحدود مبدئية وتُراجع بعد مراقبة الاستخدام. حد الحافة 50/دقيقة تقريبي لكل مركز Cloudflare وليس عالميًا.
## حدود خطة Cloudflare

يمكن استخدام SQLite Durable Objects على Workers Free. لكن حدود Worker المجانية وDurable Objects المجانية تُحسب يوميًا، وتختلف عن حدود الدقيقة التي يفرضها الكود. توضح Cloudflare حاليًا حد 100,000 طلب Worker يوميًا وحد 100,000 طلب Durable Object يوميًا للخطة المجانية؛ وبعد تجاوز حد يومي مجاني تتوقف العمليات من النوع المتجاوز إلى وقت إعادة الضبط. لذلك تُستخدم البوابة في البداية لعدد زوار محدود وتُراقب لوحة الاستخدام قبل توسيعها.

## النشر عبر GitHub Actions

سير `.github/workflows/deploy-anwar-api-gateway.yml` يعمل بطريقتين مضبوطتين:
- تلقائيًا بعد نجاح `Quality checks` على `main` من المستودع الأصلي، إذا اختلفت ملفات العامل أو سياسة نشره عن آخر نشر ناجح.
- يدويًا من تبويب Actions عند اختيار فرع `main` فقط.

لا ينشر عند فشل الجودة، ولا بسبب تشغيل فحوص Pull Request أو فروع المعاينة. ويستخدم الالتزام نفسه الذي اجتاز الجودة. صلاحيات GitHub الممنوحة للسير هي `contents: read` و`actions: read` فقط.

**التهيئة الأولى بأقل صلاحيات:**

1. أنشئ Worker باسم `anwar-api-gateway` من لوحة Cloudflare مرة واحدة، حتى يمكن قصر رمز النشر على هذا العامل بدل منحه صلاحية إنشاء وحذف كل عمال الحساب.
2. أنشئ Cloudflare API Token مخصصًا بصلاحية نشر/تعديل Worker المحدد (`Workers Scripts Write` أو دور `Workers Editor`) مع صلاحية قراءة بيانات نطاق Workers الفرعي اللازمة لاستخراج عنوان `workers.dev`. لا تمنح صلاحيات DNS أو الحساب الكاملة.
3. أضف Account ID إلى GitHub Secrets.
4. أنشئ `IP_HASH_SECRET` عشوائيًا لا يقل عن 32 بايت، و`ADHKAR_ADMIN_SECRET` عشوائيًا مستقلاً لا يقل عن 32 محرفًا. لا ترسل أي سر في المحادثة أو في ملفات المستودع.

**أسماء GitHub Repository Secrets المطلوبة:**
- `CLOUDFLARE_API_TOKEN`: رمز Cloudflare المحدود للعامل وقراءة نطاق Workers الفرعي.
- `CLOUDFLARE_ACCOUNT_ID`: معرّف حساب Cloudflare.
- `IP_HASH_SECRET`: سر HMAC لتجزئة عنوان IP قبل إدخاله في عدادات المعدل.
- `ADHKAR_ADMIN_SECRET`: سر إدارة المالك، منفصل عن سر HMAC.

ينشئ سير النشر ملف الأسرار مؤقتًا بصلاحية `600`، ويستخدم إصدار Wrangler مثبتًا، ثم يحذف الملف وملف اعتماد Cloudflare المؤقت دائمًا. بعد النشر يستعلم من واجهة Cloudflare الرسمية عن نطاق `workers.dev` للحساب، ويتحقق من بنيته، ثم يشغّل اختبارًا حيًا على العنوان الدقيق. لا يطبع الاختبار الأسرار.

**التحقق الحي بعد النشر يشمل:**
- وصول قائمة القراء والمحطات وبنية JSON المتوقعة.
- القراءة العامة لمكتبة الأذكار واستجابة مخزن Durable Object.
- منع قراءة وكتابة إدارة المالك دون جلسة صالحة.
- CORS للأصل المسموح ورفض الأصل غير الموثوق.
- رفض المسارات المجهولة والطرق غير المسموحة ومعامل URL الخارجي ورموز البلدان والمعرّفات غير الصالحة.

يبقى `ANWAR_API_GATEWAY_BASE` في موقع الويب فارغًا في هذه المرحلة. هذا مقصود: نجاح نشر العامل واختباره لا يغيّر حركة الموقع تلقائيًا. يتم ربط الواجهة في مرحلة مستقلة بعد نجاح اختبار الإنتاج ومراجعة توافق الإذاعات والمكتبة، مع تحديث CSP لأصل Worker المحدد فقط.
## حدود هذه الطبقة

هذه البوابة تحمي طلبات **البيانات** التي تمر عبرها. ملفات MP3 والبث المباشر ما زالت تُحمّل من مضيفي الصوت مباشرة حتى لا نمرر تدفقًا كبيرًا عبر Worker. كما أنها لا تمنع هجومًا موزعًا واسعًا من آلاف العناوين على Worker نفسه؛ عند ربط نطاق مخصص بـCloudflare يمكن إضافة WAF Rate Limiting Rules وتحديات البوتات عند الحافة. لا تجعل CORS وحده وسيلة مصادقة؛ يمكن لأي عميل غير متصفح تزوير ترويسة Origin.


## المسارات غير المتاحة

لا يوفّر العامل تفريغًا لملفات الصوت أو الفيديو، ولا يستخرج ترجمات من روابط YouTube. يقتصر على مسارات البيانات المحددة أعلاه؛ وتُرفض طلبات `POST` غير المدعومة.

## مكتبة أذكار التحصين — تحكم المالك فقط

تحفظ الأذكار الرسمية المعتمدة في SQLite داخل Durable Object مستقل باسم `ADHKAR_STORE`. يستطيع الزوار قراءة القائمة فقط؛ أما الإضافة والتعديل والحذف وتهيئة النسخة الأولى فتتطلب جلسة مالك موقعة من الخادم.

### إعداد سر الإدارة

1. أنشئ رمزًا عشوائيًا طويلًا (64 حرفًا أو أكثر) باستخدام مدير كلمات مرور موثوق. لا تستخدم كلمة مرور سبق استعمالها.
2. أضف الرمز إلى GitHub Repository Settings → Secrets and variables → Actions باسم `ADHKAR_ADMIN_SECRET`.
3. شغّل سير العمل `Deploy Anwar API Gateway`. يجب أن تكون الأسرار الأربعة موجودة: `CLOUDFLARE_API_TOKEN` و`CLOUDFLARE_ACCOUNT_ID` و`IP_HASH_SECRET` و`ADHKAR_ADMIN_SECRET`.
4. بعد معرفة عنوان Worker المنشور، ضعه في `api-gateway-config.js` داخل `ANWAR_API_GATEWAY_BASE`، ثم انشر صفحة المفكرة.
5. افتح «إدارة المالك» وسجّل الدخول، ثم اضغط «تهيئة القائمة الحالية» مرة واحدة لنقل الأذكار الحالية إلى المكتبة المشتركة.

### الصلاحيات

- `GET /v1/adhkar` — قراءة القائمة الرسمية فقط. لا يقبل هذا المسار أي إضافة أو تعديل أو حذف.
- `POST /v1/admin/session` — إنشاء جلسة مالك موقعة مدتها 20 دقيقة.
- `GET /v1/admin/adhkar` — قراءة المكتبة داخل لوحة المالك.
- `POST /v1/admin/adhkar/initialize` — نقل القائمة المحلية الحالية مرة واحدة فقط.
- `POST /v1/admin/adhkar` و`PUT /v1/admin/adhkar` و`DELETE /v1/admin/adhkar/{id}` — إضافة الأذكار الرسمية أو تعديلها أو حذفها. كل هذه العمليات محمية بالجلسة على الخادم.

### خصوصية الزوار

- أزيلت واجهة اقتراحات الزوار ومسارات استقبالها وصندوق المراجعة من التطبيق والخادم.
- يحذف العامل جدول الاقتراحات القديم عند تهيئة المخزن، حتى لا يبقى صندوق مساهمات قديم في قاعدة البيانات.
- قراءة الأذكار العامة تستخدم حدًا عند حافة Cloudflare لكل عنوان شبكة بمفتاح HMAC مؤقت مشتق من العنوان؛ لا يُرسل العنوان الخام إلى مخزن التطبيق ولا يُحفظ في قاعدة بياناته أو كسجل قراءة. ويظل الزائر بلا حساب أو ملف شخصي.
- لا توجد ملفات تعريف أو حسابات أو بريد أو هاتف أو بيانات مساهمين مرتبطة بمكتبة الأذكار.
- طلبات قراءة المكتبة تستعمل بصمة HMAC مؤقتة عند حافة Cloudflare لتحديد المعدل لكل شبكة، كما تُحمى محاولات دخول المالك بمحدد المعدل الحالي. لا يُحفظ عنوان IP الخام في مخزن المكتبة أو قاعدة بيانات التطبيق.
- جلسة المالك تبقى في ذاكرة الصفحة ولا تُحفظ في `localStorage` أو `IndexedDB`، وتنتهي بعد 20 دقيقة أو عند إغلاق لوحة الإدارة.
- يعرض التطبيق نصوص الأذكار عبر `textContent` ولا يفسرها كـHTML.

لا تضع قيمة `ADHKAR_ADMIN_SECRET` في أي ملف أو رسالة أو متغير واجهة. تبقى في GitHub Actions Secrets ويحقنها Wrangler كسر مشفر في Worker.
