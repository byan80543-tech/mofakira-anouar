## 2026-11-22 — أيقونة التحديث داخل التطبيق وتحديثات Android الموقعة (0.9.7)

- تظهر أيقونة تحديث عائمة داخل التطبيق عند نشر إصدار Android أحدث، وتتحقق المفكرة من الإصدار المنشور عند فتح التطبيق ثم كل ست ساعات.
- يفحص المحدّث هوية الحزمة ورقم البناء ومصدر الرابط، وينزّل APK من إصدار GitHub الرسمي فقط، ويتحقق من SHA-256 ثم من اسم الحزمة ورقم الإصدار قبل فتح مثبت Android.
- لا يوجد تثبيت صامت: يوافق المستخدم على التنزيل، ثم يتولى Android عرض نافذة تثبيت الحزمة. يتطلب Android 8+ السماح مرة واحدة لمفكرة أنوار بتثبيت التطبيقات من هذا المصدر.
- لا تعمل آلية تحديث APK في نسخ Debug التجريبية؛ لأن لكل معاينة معرّف حزمة منفصلًا. تبدأ التحديثات داخل التطبيق بعد تثبيت أول إصدار إنتاجي موقّع.
- سير العمل `.github/workflows/android-release.yml` ينشر إصدارًا رسميًا عند دمج إصلاحات التطبيق إلى `main`، بشرط إعداد أسرار التوقيع الأربعة مرة واحدة في GitHub Actions. من دونها يتخطى النشر الرسمي ولا يفشل بناء المعاينة.
- يجب الاحتفاظ بملف مفتاح التوقيع الخاص ونسخة احتياطية آمنة منه؛ لا يُرفع إلى المستودع ولا يُرسل في المحادثات. تغيير المفتاح لاحقًا يمنع Android من قبول التحديث فوق النسخة المثبتة.
- إصدار المعاينة الحالي 0.9.7، رقم البناء 16، ومعرّف التثبيت الجانبي `.preview.v16`.

### إعداد التحديثات الرسمية مرة واحدة

أنشئ مفتاح توقيع Release خاصًا بالمشروع في مكان آمن باستخدام `keytool`، واحتفظ بنسخة احتياطية خارج GitHub. بعد ذلك أضف القيم التالية في المستودع: Settings → Secrets and variables → Actions → New repository secret:

1. `ANWAR_RELEASE_KEYSTORE_BASE64`: محتوى ملف keystore بعد ترميزه Base64.
2. `ANWAR_RELEASE_STORE_PASSWORD`: كلمة مرور ملف keystore.
3. `ANWAR_RELEASE_KEY_ALIAS`: اسم المفتاح داخل الملف.
4. `ANWAR_RELEASE_KEY_PASSWORD`: كلمة مرور المفتاح.

أمر إنشاء المفتاح على جهاز موثوق يحتوي على Java:

```bash
keytool -genkeypair -v -keystore anwar-release.jks -alias anwar-release -keyalg RSA -keysize 4096 -validity 10000
base64 -w0 anwar-release.jks
```

لا ترسل ملف keystore أو كلمات المرور إلى ChatGPT أو تضعها في ملفات المستودع. بعد حفظ الأسرار الأربعة، ينشر سير العمل إصدارات APK موقّعة تلقائيًا عند كل إصلاح مدمج إلى `main`. أول انتقال من نسخة Preview ذات معرّف منفصل إلى النسخة الرسمية يحتاج تثبيت النسخة الرسمية مرة واحدة؛ بعد ذلك تظهر أيقونة التحديث داخل التطبيق عند توفر كل إصدار جديد.
