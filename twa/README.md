# تغليف مفكرة أنوار الأصلية إلى Android (TWA)

هذا المسار مخصص لتغليف **الموقع المنشور نفسه** كتطبيق Android باستخدام Trusted Web Activity (TWA) وBubblewrap. لا ينشئ واجهة بديلة ولا ينسخ التطبيق إلى مشروع مستقل.

## المصدر المعتمد الوحيد

- صفحة البدء: https://mofakira-anouar.pages.dev/mofakira-anouar/
- Web Manifest: https://mofakira-anouar.pages.dev/mofakira-anouar/manifest.webmanifest
- Service Worker: https://mofakira-anouar.pages.dev/mofakira-anouar/service-worker.js

يُحافظ التطبيق على نفس الأصل ومسار المفكرة؛ لا توجد نسخة HTML مستقلة داخل APK، ولا تتم إعادة بناء ميزات الكتابة أو الخزنة أو الإذاعات.

## ما تحقق من المصدر

- `index.html` يربط `manifest.webmanifest` ويستخدم مسارات نسبية متوافقة مع مسار التطبيق.
- `manifest.webmanifest` يحدد `id` و`start_url` و`scope` على `/mofakira-anouar/`، ويعرّف أيقونتي 192 و512 بكسل.
- `app-core.js` يسجل `service-worker.js` باستخدام نطاق نسبي `./`.
- سير عمل Cloudflare Pages يبني الملفات في `dist/mofakira-anouar/`، ويضع `_headers` في جذر النشر.

هذه مراجعة للمصدر في المستودع. لم نتمكن من إجراء طلب HTTP حي من بيئة التنفيذ الحالية، لذلك لا نسجل نجاح فحص الإنتاج أو بناء APK.

## هوية حزمة TWA

- اسم التطبيق: مفكرة أنوار
- package ID: `com.anwar.mofakira.twa`
- نقطة البدء والنطاق: `/mofakira-anouar/`
- أقل إصدار Android: API 24 (متطلب مكتبة Android Browser Helper 2.8.0)
- تفويض الإشعارات: معطل افتراضياً
- النمط: TWA مع رجوع Custom Tabs عند فشل التحقق

اختير معرّف مستقل ينتهي بـ `.twa` حتى لا يتعارض مع معرّف مشروع Android القديم `com.anwar.mofakira`. هذا لا يغيّر بيانات الموقع ولا يمسها.

## شرط إثبات الملكية

قبل إزالة واجهة المتصفح نهائياً، يجب نشر الملف:

`https://mofakira-anouar.pages.dev/.well-known/assetlinks.json`

ويجب أن يتضمن بصمة SHA-256 **الفعلية** لشهادة توقيع APK/ AAB النهائي، مع package ID أعلاه والعلاقة `delegate_permission/common.handle_all_urls`.

لا تضع بصمة تخمينية ولا ترفع keystore أو كلمات مروره إلى Git. ملف `assetlinks.json` لا يُنشأ قبل حسم مفتاح التوقيع النهائي. إذا فشل التحقق، يعرض Chrome الموقع داخل Custom Tab بدلاً من TWA كاملة الشاشة.

## الحفاظ على الموقع والبيانات

- لا يغيّر التغليف ملفات بيانات المفكرة أو محتواها.
- تظل الصفحة تعمل من عنوانها الأصلي داخل Chrome؛ لذلك تظل بيانات الويب مرتبطة بأصل الموقع وملف Chrome نفسه.
- لا يُجرى نقل أو مسح أو تهيئة للخزنة المشفرة أثناء التغليف.
- تحديث الموقع المنشور يظهر داخل التطبيق عند تحميله؛ ولا يعني هذا أن كل الميزات تعمل دون اتصال.

## التحقق والبناء التجريبي

ملف `.github/workflows/twa-preview.yml` يشغّل Bubblewrap CLI بالإصدار المثبت `1.28.0`، ويتحقق من عنوان الموقع المعتمد، ثم يولّد مشروع TWA ويترجم مخرجات غير موقعة وAPK تشخيصياً. لا يُعد أي ناتج من هذه المرحلة إصداراً نهائياً أو دليلاً على نجاح TWA كاملة الشاشة قبل نشر `assetlinks.json`.

## الخطوات المتبقية قبل APK نهائي

1. تنفيذ فحص HTTP حي للموقع وManifest وService Worker والأيقونات.
2. بناء نسخة اختبار غير إنتاجية وتثبيتها على Samsung Galaxy XCover 5.
3. اختبار فتح الموقع، والتنقل داخل نطاقه، والكتابة والحفظ، وفتح الخزنة، والسبحة، والإذاعات واستمرار الصوت، والرجوع للخلف، والاتصال/انقطاعه.
4. اعتماد مفتاح توقيع نهائي محفوظ خارج Git، ثم حساب بصمة SHA-256 منه.
5. نشر `.well-known/assetlinks.json` في جذر النطاق، لا داخل مجلد التطبيق، ثم إعادة اختبار التحقق.
6. إصدار APK/AAB موقّع بعد نجاح الاختبارات.

## وضع المشروع القديم

المجلد `android/` خارج مسار التغليف الجديد ومحفوظ كما هو للأرشفة والاسترجاع. لا يُبنى منه APK جديد ضمن هذه الخطة، ولا يُحذف أو يُنقل أثناء تجهيز TWA حتى لا تتأثر الملفات أو سجلات البناء القديمة.
